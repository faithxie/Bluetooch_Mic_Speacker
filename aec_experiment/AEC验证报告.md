# AEC 可行性验证报告

**结论：这个模型不适合 BTSPK 的啸叫场景。建议不接入。**

原判据是「能降 15 dB 以上就值得接入」。答案是：**在 BTSPK 的真实工作点下做不到。**

---

## 1. 背景与验证目标

BTSPK 的啸叫环路：

```
mic → 我们的 DSP(陷波+移频+门限) → 扬声器 → 空气 → mic
```

陷波/移频/门限都是**被动响应**（啸叫已经出现后才压）。AEC 是**主动预测**：
它手里有即将播出的 `outdata` 作为远端参考，可以在漏音累积之前把它减掉，
理论上比陷波更根本。

候选方案来自 `LanRhyme/MicYou` 依赖的 `a2heng/lightweight-aec-48k`（MIT）。

---

## 2. 模型与运行器

| 项目 | 值 |
|---|---|
| 模型 | `aec7_ep0185.onnx` (4.7 MB)，来自 `a2heng/lightweight-aec-48k`，MIT |
| 采样率 | 48 000 Hz |
| hop / win / FFT | 480 / 960 / 960 samples（10 ms / 20 ms） |
| 频点数 | 481 |
| 窗函数 | sqrt-Hann（周期性，`0.5 - 0.5·cos(2πn/960)`） |
| 输入输出 | 14 进 14 出（2 个 STFT 帧 + 12 个缓存张量） |
| 推理依赖 | `onnxruntime`（纯 Python，**不需要**上游的 C++ 扩展） |
| 实测性能 | **5.3 ms / 帧**（预算 10 ms），约 53% 单核占用 |

### 运行器：`aec_onnx_runner.py`

上游 `aec_processor.py` 依赖 pybind11 + MSVC 编译的 `aec_inference` 模块，
仓库里没有二进制，因此重写为纯 NumPy + onnxruntime 流式实现。
过程中修正的三个实现要点（都是上游代码/文档的坑）：

1. **输出张量必须按名字映射，不能按位置。**
   模型声明 14 个输出，但第 6 个 `deep_enc_conv_o` 形状为 `(1, 0)`
   且**没有对应输入**，是死张量。按位置 zip 会让其后所有缓存错位。

2. **合成端必须用 WOLA（加权重叠相加）。**
   上游文档的 `irfft` 后直接取 `y[:480]` 会丢掉一半窗能量。
   sqrt-Hann 的互补性恰好成立：

   ```
   w[k]² + w[k+480]² = 1.000000   （实测，误差 <1e-6）
   ```

   用同一 sqrt-Hann 做合成窗并重叠相加，往返增益 **−0.06 dB、
   相关性 1.000000、最大误差 6e-8**。按上游写法会有恒定 **−3.00 dB** 损失。

3. **输出天然延迟两跳（960 采样）。**
   帧分析的 960 点缓冲覆盖「上一跳+当前跳」，完成的是**较旧**那一跳。
   把输出平移 960 采样后与输入相关性 = 1.000000。已在 `process_stream` 补偿。

> 运行器本身是**正确**的：白噪声下能收敛（18 dB → 27 dB 并稳定），
> 12 个缓存张量逐帧正常更新（`max|Δ|` 量级 1e0–2e1）。
> 下面的结论是**模型行为**，不是实现 bug。

## 3. 决定性发现：双讲时模型完全冻结

真实语音（VB-Audio Virtual Cable 回环录制的 TTS，48 kHz，36.6 秒），
`far` 与 `near` 取自不同片段，ground truth 已知。

固定回声为 −12 dB、延迟 30 ms，**只改变近端电平**：

| 近端/回声比 | 近端电平 | 回声电平 | **ERLE** |
|---|---|---|---|
| −60 dB | 0.00003 | 0.01082 | **35.34 dB** |
| −40 dB | 0.00032 | 0.01082 | 19.80 dB |
| −30 dB | 0.00102 | 0.01082 | 20.49 dB |
| −24 dB | 0.00204 | 0.01082 | 17.68 dB |
| −20 dB | 0.00324 | 0.01082 | 14.30 dB |
| −16 dB | 0.00513 | 0.01082 | 11.75 dB |
| −12 dB | 0.00813 | 0.01082 | 8.62 dB |
| −6 dB | 0.01623 | 0.01082 | 4.34 dB |
| **0 dB（等强）** | 0.03237 | 0.01082 | **0.12 dB** |
| +6 dB | 0.06460 | 0.01082 | −4.24 dB |

同一组参数（延迟 30 ms、衰减 −12 dB）下改变 mic 内容：

| mic 内容 | ERLE |
|---|---|
| 只有回声（无近端） | **64.07 dB** |
| 回声 + 近端 | **0.12 dB** |
| 只有近端（far 不进 mic） | 0.45 dB |

**只要 mic 里出现近端说话声，AEC 就几乎完全停止工作。**

这是教科书式的**双讲检测（Double-Talk Detection）保护**：
模型宁可放过回声，也不愿冒削减本地人声的风险。方向是对的、业界标准做法，
但对我们的场景是致命的。

---

## 4. 为什么这个特性对 BTSPK 是致命的

关键点在于**回声和近端在物理上无法分离**。

在 BTSPK 里：

```
mic 采集到的 = 用户说话声  +  扬声器漏音  +  啸叫
```

- 用户**说话时**：近端很强 → AEC 冻结 → 啸叫照样啸
- 用户**不说话时**：近端为 0 → AEC 全开 → 但此时往往正是**啸叫最容易
  建立**的时刻（没有语音掩蔽，纯净的正反馈迅速起振）

两者是错开的。也就是说 **AEC 恰好在最需要它的时候被关闭**。

更糟的是：当近端比回声强（正是用户正常说话的情形，`+6 dB` 那一行），
ERLE 变成 **−4.24 dB**，即输出里回声反而**变大**了。这不是抵消，是放大。

### 另一个门槛：延迟要 ≥ 20 ms

`far` 只延迟不衰减的扫描（真实语音，衰减 −12 dB）：

```
 0 ms :  0.28 dB      10 ms :  5.19 dB      20 ms : 32.55 dB
 2 ms :  0.32 dB      12 ms :  8.50 dB      25 ms : 49.76 dB
 5 ms :  0.75 dB      15 ms : 11.71 dB      30 ms : 64.07 dB
 8 ms :  1.95 dB      18 ms : 17.48 dB      50 ms : 66.92 dB
```

（这张表是**只有回声、没有近端**时测的，所以数字很漂亮 —— 也正说明
「没有近端」这个前提才是决定性的。）

延迟门槛的原因：模型是按**网络回声**训练的（远端参考经网络往返 >100 ms
才回到本地）。0–5 ms 的延迟在训练分布之外，它把这种「几乎同时到达」的
信号判为近端本人说话，于是原样保留。

频率维度的旁证（`far == mic` 时的抑制）：

| 信号 | 抑制 |
|---|---|
| 白噪声（能量主要 >3.4 kHz） | 27.5 dB |
| 300–3400 Hz 带限噪声（人声区间） | 1.1 dB |
| 单音 1 kHz | 0.0 dB |
| 扫频 | 0.0 dB |
| **真实语音** | **0.0 dB** |

模型只在「明显不像人声」时工作。

## 5. 判据结论

| 问题 | 答案 |
|---|---|
| 能降 15 dB 以上吗？ | **不能** —— 真实工作点（近端与回声同量级）下只有 0.1–8 dB |
| 什么时候能降 15 dB 以上？ | 只在**没有近端人声**、且参考领先 ≥ 20 ms 时 |
| 这个条件在我们的拓扑里成立吗？ | **不成立** —— mic 里必然有用户说话声 |
| 语音会被损伤吗？ | 不会（近端相关性 0.99+，电平 −0.3 dB），但代价是它也不干活 |
| 实时性够吗？ | 够（5.3 ms/帧），这不是瓶颈 |
| **值得接入吗？** | **不值得** |

---

## 6. 建议

**保持现有方案，不要接入这个 AEC。**

现有的「多判据检测 + 陷波 + 真移频 + 门限」链路是**正确的方向**，因为：

- **移频**解决的是相位条件（把 0°/360° 的相位对齐点不断挪走），
  对**非线性**环节（扬声器削顶、功放饱和、蓝牙编解码）依然有效 ——
  而 AEC 作为线性自适应滤波器对非线性无能为力。
- **多判据检测**能在混有语音的情况下识别啸叫，这正是 AEC 双讲检测
  放弃的那部分工作。
- 泛用 AEC 模型的双讲保护与我们的需求**方向相反**。

### 如果仍然想要 AEC

需要找**专为当地声学回声**（延迟 1–30 ms、非网络）训练、且
**双讲期间仍保持部分抑制**的模型，或者：

1. 用 `far` 做**线性回声路径辨识**（NLMS/RLS 自适应 FIR），自己实现
   抑制而不是用这个模型。好处是双讲时可以自由选择「保持自适应」策略。
2. 如果坚持用本模型，必须**先做延迟对齐**（≥20 ms），并且接受
   「用户说话时 AEC 失效」这一事实 —— 此时仍需依赖移频兜底。

无论哪条路，**移频都不能拿走**。

### 验证过程中排除的三个假象

避免后续误判，记录一下走过的弯路：

1. **合成谐波信号不可用。** 用「完美周期」的谐波堆叠做探针时会得到
   恒定 3.02 dB 的假象（对任何延迟/衰减都一样），因为周期性信号对
   这个模型是退化输入。**必须用真实语音**。
2. **合成端取半个窗会引入 −3.00 dB 恒定损失。** 一度被误读为
   「模型损伤人声」，实际是 WOLA 未补偿。已用互补性恒等式排除。
3. **`process_stream` 少补一跳。** 表现为「输出与人声相关性 ≈ 0」，
   看起来像模型把人声毁了，实际是输出整体滞后 960 采样。
   平移后相关性 1.000000。
