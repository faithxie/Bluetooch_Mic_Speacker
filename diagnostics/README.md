# diagnostics — 诊断与验证脚本

这些脚本用于**定位问题、量化验证算法效果**，不是程序运行的一部分。
平时不影响主程序，可安全忽略。

## 运行方式

所有脚本都自己把项目根目录加入了 `sys.path`，所以可以二选一：

```bash
# 方式一：从项目根运行（推荐）
venv\Scripts\python.exe diagnostics\test_chain_e2e.py

# 方式二：进入目录运行
cd diagnostics
..\venv\Scripts\python.exe test_chain_e2e.py
```

## 脚本清单

| 脚本 | 作用 | 现状 |
|---|---|---|
| `test_chain_e2e.py` | **端到端链路验证**（主力回归测试）。验证：人声不被误伤、啸叫能被检出、输出无 NaN、移频量准确 | ✅ 全部通过 |
| `debug_v2.py` | 逐判据打印候选峰的 PNPR / PHPR / IMSD 数值，用于调阈值 | ✅ 可运行 |
| `debug_shifter.py` | 调查移频器的频谱异常（已定位并修复为 FIR Hilbert 实现） | ✅ 可运行 |
| `diag_howling.py` | 量化**旧版**算法对音质的破坏（颤音/误伤共振峰/噪声门） | ✅ 可运行（复现历史问题） |
| `diag_deep.py` | 用更真实的人声验证**旧版**陷波的误伤率 | ✅ 可运行 |
| `diag_validate_fix.py` | 验证「多判据 AND 融合」方案对比单判据的效果 | ✅ 可运行 |

> `diag_howling.py` / `diag_deep.py` 里的「旧版算法」指 `feedback_suppressor_deprecated.py`。
> 它们的存在是为了**保留问题复现能力**，方便日后回归时对照。
